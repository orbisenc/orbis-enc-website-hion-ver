# 보안 및 개인정보 보호

## 위협 모델

주요 위협은 다른 테넌트 ID 추측, 초대 토큰 탈취, 중복·동시 제출, 관리자 계정 탈취, CSV 수식 주입, 악성 업로드, 경로 순회, 개인정보 로그 노출입니다. 서버는 URL ID를 신뢰하지 않고 세션 테넌트로 모든 업무 조회를 제한해야 합니다.

## 적용된 통제

- 관리자 세션은 HttpOnly, SameSite 쿠키와 HMAC 서명을 사용하며 운영 HTTPS에서 Secure가 적용됩니다.
- 로그인·OTP 요청에 속도 제한과 동일한 한국어 실패 응답을 적용합니다.
- Zod 입력 검증, Prisma 매개변수 쿼리, React 기본 이스케이프를 사용합니다.
- 로컬 저장소는 절대 경로 정규화와 `..` 거부로 작업 폴더 밖 접근을 막습니다.
- 업로드 공급자 계약에 확장자·MIME·크기 검사와 악성 파일 검사 단계를 둡니다.
- 원시 주민등록번호 필드가 없고, 연락처는 암호문과 검색 해시로 분리합니다.
- 응답 선택, OTP, 전화번호, 초대 토큰을 로그에 기록하지 않습니다.
- 감사·증거 레코드는 애플리케이션에서 수정·삭제하지 않습니다.
- 안건 초안·검토·승인·게시와 현황 설정·일시중지·마감·결과 확정·재안내를 역할별로 분리하고 추가 전용 처리 이력에 남깁니다.
- 첨부 자료는 허용 MIME뿐 아니라 PDF·JPEG·PNG·WebP·MP4 파일 서명을 검사하고 SHA-256 중복 파일을 차단합니다. 삭제는 안건·테넌트 범위와 동일 출처를 확인합니다.
- 보고서와 증거 명세는 5자 이상의 내보내기 사유를 요구하고 처리자·시각·목적을 기록하며 `no-store`로 반환합니다.

## 운영 전 필수 조치

모의 OTP, 내부 알림함, 로컬 파일 저장소, 비활성 전자서명을 실제 승인 공급자로 교체해야 합니다. 공유 Redis 속도 제한, CSRF 원본 검증, 키 관리 시스템 기반 필드 암호화, 악성 파일 검사, 객체 저장소 비공개 버킷, 백업 암호화, 보안 헤더 CSP, 관리자 TOTP 복구 정책을 운영 환경에 적용해야 합니다.

`LEGAL_CONSENT`는 `ENABLE_LEGAL_CONSENT=true`, 비모의 본인확인 공급자, 활성 전자서명 공급자를 동시에 만족하기 전 게시를 거부합니다. 법적 효력 판단은 반드시 별도 법률 검토를 거쳐야 합니다.

## 관리비 금융정보 통제

- 세대별 관리비 화면과 보고서는 이름·연락처를 기본 포함하지 않고 동·호수와 원장 상태만 표시합니다.
- `ACCOUNTING_MANAGER`는 등록·대사·조정·보고, `APPROVER`는 확정·마감·재개, `AUDITOR`는 읽기·보고·감사, `CONTENT_EDITOR`는 안건 비용 설명만 수행합니다.
- `PLATFORM_ADMIN`은 활성 기간의 감사된 지원 승인이 없으면 단지·세대 관리비를 조회할 수 없습니다. 승인 중에도 가져오기·조정·마감 권한은 부여하지 않습니다.
- 세션 테넌트와 대상 테넌트를 모든 관리비 서비스에서 비교합니다. URL의 단지·기준월 식별자를 권한 근거로 사용하지 않습니다.
- CSV 원본은 파일 해시로 중복을 차단하고 비공개 저장소에 보관합니다. 확장자·MIME·크기·NUL 바이트·인코딩을 검사하며 운영에서는 악성 파일 검사 공급자를 추가합니다.
- CSV 오류에는 행 번호와 한국어 설명만 표시하고 원시 금융 행, 이름, 연락처를 로그·브라우저 콘솔·오류 추적에 보내지 않습니다.
- 세대별 조회, 가져오기 확정, 조정·승인, 확정·마감·재개, 보고서 생성, 안건 비용 승인 이벤트를 추가 전용 감사 이력에 기록합니다.
- CSV 셀의 수식 시작 문자를 이스케이프하며, 보고서에는 상태·생성 시각·필터·스냅샷 식별자와 잠정 또는 확정 안내를 포함합니다.
