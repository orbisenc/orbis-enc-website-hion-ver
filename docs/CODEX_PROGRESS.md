## 결정과 가정

- 제3자 자격증명 없이 시연하도록 실행 화면은 프로세스 내 개발 저장소를 사용한다. 운영 전 Route Handler를 준비된 Prisma 서비스/저장소로 전환한다.
- `LEGAL_CONSENT`는 기능 플래그와 실제 본인확인·전자서명 공급자가 모두 없으면 활성화할 수 없다.
- Windows E2E는 설치된 Chrome을 사용하고, Playwright 완료 리포터로 결과를 확인한 뒤 개발 서버 프로세스 트리를 정리한다.
- 한국어 PDF는 Windows 맑은 고딕을 자동 탐색하고 다른 환경에서는 `KOREAN_PDF_FONT_PATH`를 요구한다.

## 검증 기록

- `pnpm install`: 성공, 648개 패키지 설치. 허용된 설치 스크립트만 실행
- `pnpm db:generate`: 성공, Prisma Client 생성
- `prisma migrate diff --from-empty --to-schema prisma/schema.prisma --script`: 성공, 34개 테이블 SQL 생성
- `pnpm typecheck`: 성공, 오류 0건
- `pnpm lint`: 성공, 경고·오류 0건
- `pnpm test`: 성공, 테스트 파일 8개·테스트 45개
- `pnpm test:e2e`: 성공, 7개 통과·공유 시연 상태를 변경하는 모바일 중복 시나리오 3개 의도적 제외. 안건 제작·검토·승인·게시, 현황 설정·재안내, 관리비와 주민 흐름 확인
- `pnpm build`: 성공, Next.js production build 및 정적 생성 대상 30개 생성
- `docker compose up -d`: 실행 불가, `docker` 명령이 설치되어 있지 않음
- `pnpm db:migrate`: 실패, `localhost:5432` PostgreSQL이 없어 schema engine 연결 실패
- `pnpm db:seed`: 실패, 같은 DB 연결 부재로 첫 `Tenant.upsert`에서 중단

## 남은 작업과 차단 사항

- Docker Desktop 또는 PostgreSQL 설치 후 `docker compose up -d; pnpm db:migrate; pnpm db:seed`를 실행해 실제 2,000행 DB 시드를 검증해야 한다.
- 브라우저 시연 Route Handler의 프로세스 내 저장소를 Prisma 저장소로 완전히 전환하는 작업은 후속 단계다.
- 실제 TOTP·본인확인·알림·전자서명·S3·악성 파일 검사 공급자 연동과 법률 검토는 운영 전 필수다.
