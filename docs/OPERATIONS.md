# 운영 안내

## 일상 점검

- PostgreSQL 연결, 디스크, 백업, 연결 풀 사용률을 확인합니다.
- 마감 전 초대 전달 실패와 본인확인 실패, 미응답 구간을 확인합니다.
- 재안내는 대상과 목적을 검토하고 과도한 발송 방지 간격을 유지합니다.
- 캠페인 종료 뒤 집계와 CSV·PDF·증거 명세의 총계를 응답 원장과 대조합니다.

## 장애 대응

영상·3D 장애는 한국어 요약과 변경 전후 이미지로 응답 흐름을 유지합니다. 제출 시간이 초과되면 같은 멱등 키로 영수증을 먼저 조회하고 새 제출을 만들지 않습니다. 데이터베이스 장애 시 캠페인을 일시 중지하고 복구 뒤 서버 시각과 감사 기록으로 영향 구간을 확인합니다.

## 안건 게시와 운영

1. `안건 제작`에서 한국어 본문·응답 문구·비용 영향·선택 첨부·3D 대체 경로의 준비도를 확인합니다.
2. 콘텐츠 담당자가 검토를 요청하고 승인자가 승인한 뒤 주민 게시를 확정합니다. 게시본 수정이 필요하면 새 버전을 만듭니다.
3. `안건 현황 관리`에서 게시 안건, 확정 명부, 시작·종료 시각, 본인확인 수준, 응답 변경 정책과 정족수를 확인합니다.
4. 진행 중 정책 변경이 필요하면 한국어 사유로 일시중지하고 변경·검증 뒤 재개합니다.
5. 미응답·발송 실패·열람 후 미인증 구간에만 필요한 재안내를 보내고, 마감 뒤 정족수와 원장 합계를 대조해 결과를 확정합니다.
6. 보고서 내보내기 목적을 기록한 뒤 CSV·PDF·증거 해시를 함께 보존합니다.

## 백업과 보존

PostgreSQL 시점 복구와 객체 저장소 버전 관리를 사용하고 복구 훈련을 정기 수행합니다. 캠페인별 보존 기간이 지나면 법률·감사 승인 절차에 따라 별도 정리 작업을 수행하되 감사 기록 자체를 화면에서 삭제하지 않습니다.

## 배포 확인

`pnpm lint`, `pnpm typecheck`, `pnpm test`, `pnpm test:e2e`, `pnpm build` 성공 후 배포합니다. 운영 시작 시 개발 모의 공급자와 기본 비밀 감지 검사를 실행하고 데이터베이스 마이그레이션을 먼저 적용합니다.

## 관리비 CSV 준비와 등록

1. `관리비 관리 → 데이터 등록`에서 기준월과 `관리비 부과` 또는 `수납·환급` 유형을 선택합니다.
2. 한국어 CSV 양식을 내려받고 UTF-8 또는 EUC-KR로 저장합니다.
3. 단지코드, 기준월, 동·호, 관리비 항목 또는 거래 정보와 안정적인 외부 식별자를 입력합니다.
4. 업로드 뒤 열 연결, 행별 차단 오류·경고, 원본 합계와 계산 합계를 확인합니다.
5. 차단 오류가 있으면 전체 묶음을 수정해 새 파일로 다시 등록합니다. 경고만 있으면 한국어 확인 사유를 남기고 확정할 수 있습니다.
6. 같은 파일 해시는 다시 등록할 수 없습니다. 정정은 새 가져오기 묶음 또는 추가 전용 조정으로 수행합니다.

2,000세대 부과 CSV 검증은 로컬 자동 테스트에서 5초 이내를 기준으로 확인합니다. 운영에서는 업로드 파일을 비공개 객체 저장소와 악성 파일 검사 공급자로 처리하고, 대용량 처리는 작업 큐로 분리합니다.

## 대사·확정·마감·재개

- 부과 합계와 수납·환급 합계, 미일치 거래, 중복 외부 식별자, 세대·항목 오류를 먼저 해소합니다.
- 승인자가 기준월을 확정한 뒤 한국어 사유를 입력해 마감합니다. 마감 시 합계 스냅샷과 해시가 생성됩니다.
- 마감 자료는 직접 수정할 수 없습니다. 필요한 경우 승인자가 한국어 재개 사유를 남긴 뒤 새 조정 또는 가져오기 이력을 추가합니다.
- 복구 뒤에는 마감 스냅샷 해시, 가져오기 파일 해시, 조정·감사 이력을 함께 대조합니다.
- CSV·PDF 보고서 합계는 마감 스냅샷과 일치하는지 확인하고, 잠정 상태 보고서는 확정 자료로 배포하지 않습니다.
