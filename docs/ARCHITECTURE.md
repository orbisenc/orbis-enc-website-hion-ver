# 아키텍처

## 구성

HION MVP는 Next.js App Router 단일 애플리케이션입니다. 주민 모바일 화면과 관리자 데스크톱 화면을 함께 제공하고 PostgreSQL을 Prisma로 접근합니다. 화면·Route Handler는 입출력만 담당하고 응답 무결성, 테넌트 격리, 상태 전이, 마감 판정은 `src/server`에 둡니다.

개발 시연은 제3자 자격증명이나 실제 개인정보 없이도 전체 UX를 검증하도록 프로세스 내 저장소를 사용합니다. 동일한 계약의 Prisma 영속 모델과 공급자 인터페이스가 준비되어 있습니다. 운영 전 데모 저장소 호출을 Prisma 저장소로 교체해야 합니다.

## 핵심 흐름

1. 초대 토큰은 원문 저장 대신 SHA-256 해시로 조회합니다.
2. 본인확인 결과를 캠페인 대상 권리와 연결합니다.
3. 게시된 안건·명부 버전은 캠페인 시작 시 고정합니다.
4. 응답은 멱등 키를 먼저 조회하고, 대상별 활성 응답을 직렬화된 트랜잭션 안에서 하나만 유지합니다.
5. 안건·동의문·콘텐츠 정규화 해시와 서버 제출 시각으로 증거 봉인 해시를 만듭니다.
6. 변경은 이전 응답을 대체 상태로 남기며 원본을 덮어쓰지 않습니다.

## 안건 제작과 현황 관리 경계

- 안건 제작은 `초안 → 검토 중 → 승인 → 게시` 상태 전이를 서버에서 강제합니다. 게시본 수정은 거부하고 새 버전을 만든 뒤 주민용 `demoAgenda` 게시 스냅샷을 갱신합니다.
- 제작 준비 점검은 한국어 본문, 고정 중립 선택지, 최종 확인문, 승인된 비용 영향과 선택 첨부·3D 대체 경로를 확인합니다.
- 안건 현황은 게시 안건과 확정 명부, 기간, 본인확인, 응답 변경, 정족수, 결과 공개 정책을 묶습니다. 진행 중 핵심 정책은 보호하고 일시중지 뒤에만 수정합니다.
- 상태 전이는 `초안 → 예약/진행 → 일시중지/마감 → 결과 확정 → 보관` 허용 목록을 사용합니다. 초대 조회, OTP, 응답 제출은 화면 상태를 신뢰하지 않고 서버에서 진행 상태와 기간을 재검사합니다.
- 시연 계약은 `src/server/demo/agenda-campaign-store.ts`에 있고 Prisma의 `Agenda`, `AgendaVersion`, `Campaign` 모델과 같은 버전·수명주기 경계를 유지합니다.

## 규모와 확장

명부·세대 API는 서버 페이지 처리를 전제로 하고 주요 조회에는 `tenantId`, 캠페인, 상태 복합 인덱스를 둡니다. 운영에서는 연결 풀, 정적 자료 CDN, 공유형 속도 제한 저장소, 작업 큐를 사용해 마감 시점 500명 동시 접속을 처리합니다.

## 3D와 미디어

React Three Fiber의 절차형 지하주차장 장면이 기본 시연 자료입니다. 명시적 조작 모드로 모바일 스크롤 충돌을 줄이고, WebGL 실패 시 한국어 설명이 붙은 변경 전후 CSS 대체 이미지를 제공합니다. 업로드 GLB는 권한 확인 URL과 동일한 뷰어 경계로 교체할 수 있습니다.

## 관리비 모듈 경계

- `src/app/admin/(secure)/fees`: 관리비 화면과 입력·출력만 담당합니다.
- `src/server/services/management-fee-ledger.ts`: 정수 원화 원장, 비율, 미납 기간, 비용 배분 계산을 담당합니다.
- `src/server/services/management-fee-import.ts`: CSV 인코딩 감지, 행 검증, 합계 대사와 원본 파일 보관을 담당합니다.
- `src/server/services/management-fee-lifecycle.ts`: 등록 확정, 기준월 확정·마감·재개와 추가 전용 조정을 담당합니다.
- `src/server/services/management-fee-auth.ts`: 역할·테넌트·지원 승인 범위를 서버에서 강제합니다.
- `src/server/demo/fee-store.ts`: 제3자 회계 시스템 없이 시연하는 결정적 2,000세대·12개월 원장 계약입니다. 운영에서는 같은 계약의 Prisma 저장소로 교체합니다.

## 관리비 원장 규칙

금액은 `bigint` 원 단위로 계산합니다. `최종 부과액 = 원 부과액 + 승인 조정액`, `순수납액 = 수납액 - 환급액`, `미납액 = max(최종 부과액 - 순수납액, 0)`, `과납액 = max(순수납액 - 최종 부과액, 0)`을 사용합니다. 비율은 basis point 정수로 계산한 뒤 화면에서 한국어 백분율로 표시합니다. 0원 분모는 `산정 불가`로 구분합니다.

마감은 기준월 합계 스냅샷과 SHA-256 해시를 만들고 원본을 덮어쓰지 않습니다. 마감 이후 변경은 승인자 재개 또는 새로운 조정·가져오기 이력으로만 수행합니다. 대시보드, 상세, CSV와 PDF는 동일한 서버 원장 집계를 사용합니다.

`AgendaCostImpact`는 편집 가능한 안건이 아니라 `AgendaVersion`에 연결됩니다. 서버가 균등·면적·의결권 배분 입력을 계산하고 스냅샷 해시를 보관하며, 주민에게는 승인된 예상 요약만 노출합니다.
